Причина

В worktree .planning — симлинк на <основной checkout>/.planning/lanes/<имя>. Любая запись туда уходит за пределы рабочего каталога сессии. Встроенная safety-проверка Claude Code спрашивает человека на каждую такую запись — и в режиме auto тоже. Хук pre-write.mjs уже отвечал allow, но safety-проверка этот ответ не учитывает: в транскриптах сразу после allow от хука идёт запрос.
  • Все сессии шли в режиме auto. Классификатор пропускал обычные команды, поэтому запросы почти полностью — это safety-проверка (reasonCode: safetyCheck).
  • 897 из 922 запросов (97%) — в worktree, и все Edit/Write с запросом — файлы .planning/.
  • Медианное ожидание ответа — 29 с на запрос. Из сессий, где запросы были (67 из 132), у медианной их 5, у p90 — 41, максимум 77.
  • Составные команды, cd … && и env-префиксы в режиме auto запросов сами по себе не вызывали: из 488 Bash-запросов все пишут в .planning/.

Что поменяно

  1. Главный фикс. Когда SessionStart-хук ставит worktree ссылку на lane, он добавляет <основной checkout>/.planning в permissions.additionalDirectories в .claude/settings.local.json этого worktree и убирает файл из git через info/exclude. Добавляется только эта папка, остальные правила файла не трогаются. Если файл — не JSON или его отслеживает git, хук его не меняет (lib/hooks/worktree.mjs, allowPlanningDirectory). Уже созданные worktree получат это на следующем старте сессии.
  2. Allowlist (поверх PR #100). К read-only правилам добавлены переходы по ledger: moku-rails open/enter/done/skip/close/pause/park/resume/continue/scope/idea/tier/guard/guard-bash/may-stop — они меняют только .planning/state.json. Плюс Edit(/.planning/**). Не добавлены: check (запускает тесты), session, init, adopt (создают файлы там, куда указывает --root). Список пишут скилл session и шаблон init; в сообщении при передаче сессии говорится, что правила убираются через /permissions.
  3. Дирижёр. Одна строка в Gotchas: текстовые файлы .planning/ писать через Write/Edit, а не shell (cat > <<EOF, sed -i, printf >>); команды запускать без cd … && и без VAR=… в начале. Это важно для режима default, где shell-запись в .planning/ не совпадёт ни с одним правилом.

Не ослаблено: push, удаление, установка пакетов, сеть, запись вне проекта и в src/ по-прежнему спрашивают. Проверено: из worktree запись в корень основного checkout блокируется и после фикса.

PreToolUse-хук с allow — не делал

  • Против главной причины он бесполезен: safety-проверка игнорирует allow от хука, и это видно в данных.
  • Для режима default те же команды закрываются правилами allowlist. Claude Code сам делит составные команды и проверяет каждую часть: moku-rails continue 2>&1 | tail -1 проходит.
  • Риск: хуку пришлось бы самому разбирать shell. Ошибка разбора дала бы allow и в обход классификатора auto, и в обход правил. Узкие правила в настройках безопаснее, и их видно в /permissions.

Режим default (оценка)

В транскриптах только режим auto. Грубая симуляция по 105 тыс. Bash-вызовов: 95% составные, 12% начинаются с cd … &&, 10% — с env-префикса, 32% пишут через shell. В режиме default без правил спрашивалось бы около 70% вызовов. Новые правила rails снимают около 1 п.п.; остальное зависит от того, перестанет ли модель писать через shell (строка в дирижёре). Без евалов в режиме default это не измерено.
