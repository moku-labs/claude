Смена аккаунта Claude на одной машине

Исследование перед фичей moku · 5 ноября 2026 · Claude Code 2.1.296 · проверки на машине только чтением, секреты и Keychain не трогались

Вывод. Технически переключение простое: транскрипты не привязаны к аккаунту, и сессии продолжаются через claude --resume <id>. Но сам сценарий — два личных Pro/Max, чтобы обойти недельный лимит — это серая зона с уклоном в нарушение. Usage Policy запрещает «create multiple accounts, to … circumvent product guardrails», а Anthropic пишет, что лимиты рассчитаны на «ordinary, individual usage». Прямого запрета на две подписки нет, но ротация ради лимита — ровно то, на что эти формулировки нацелены. Ротацию строить не предлагаю. Предлагаю тот же механизм (чекпойнт, смена входа, продолжение), но для допустимых переходов: Extra usage, API-ключ из Console, рабочий Team-аккаунт, апгрейд плана.

Оговорки: AUP на сайте датирована 12 ноября 2026 (через неделю), формулировки выше взяты со страницы как она есть. Consumer Terms агент получил в версии для ЕЭА; запрет делиться учётными данными есть во всех версиях. Что считать «guardrail» — нигде не определено, это толкование.

Допустимые способы получить больше:

  • Extra usage (usage credits) — доплата по API-тарифам сверх лимита с месячным потолком; в Claude Code это /usage-credits. Справка
  • Апгрейд плана — Max → Ultra (бывший Max 20x). Ultra
  • API-ключ из Console — claude auth login --console или ANTHROPIC_API_KEY, оплата за токены.
  • Team/Enterprise — рабочий аккаунт рядом с личным разрешён явно, но место в Team принадлежит одному человеку.
  • Подождать — autoContinueAtUsageLimit: Claude Code сам продолжит после сброса лимита.

3. Продолжить сессию под другим входом

ПутьЧто выходит
Одна папка конфигурации, claude auth logout → loginТранскрипты общие, claude --resume <id> и --continue находят все сессии. Сбрасываются первичная настройка и серверные настройки. Самый простой путь. На живом переключении не проверял.
Профили CLAUDE_CONFIG_DIRКаждый профиль со своей историей: сессии A не видны из B. Плагины и marketplace нужно ставить в каждый профиль. Оба профиля можно держать залогиненными одновременно.
Десктоп, вкладка CodeСписок сессий в боковой панели, по-видимому, свой для каждого аккаунта, но транскрипты общие. Сессию можно продолжить через claude --desktop --resume <id> или из CLI. Как десктоп ведёт себя при смене аккаунта, не документировано.

Что теряется при продолжении: кэш промптов (первый запрос — полный объём контекста по полной цене); фоновые Bash и субагенты (помечаются «did not finish»); флаги запуска (--add-dir, --mcp-config, --settings); Remote Control, cloud-сессии и teleport (они только под своим аккаунтом); коннекторы claude.ai и OAuth для MCP, если они привязаны к аккаунту. Разговор, модель, режим разрешений и незавершённые вызовы инструментов восстанавливаются. Sessions

4. Что в moku зависит от аккаунта

  • Ничего существенного. .planning/, state.json, ledger с lanes по worktree, хуки — всё живёт в проекте и привязано к папке, а не к аккаунту.
  • Привязка сессии к рельсам лежит в ~/.claude/moku/sessions/<session-id>.json (plugins/moku/lib/hooks/root.mjs). Путь прописан жёстко, MOKU_HOME его переопределяет, CLAUDE_CONFIG_DIR на него не влияет. Поэтому при --resume с тем же id привязка сохраняется, а при --fork-session id новый — нужен повторный moku-rails session start.
  • Плагины установлены в user scope, в ~/.claude/plugins. Новый профиль CLAUDE_CONFIG_DIR = заново marketplace и 12 плагинов.
  • Мелкий баг: hooks/detect-moku-project.sh читает $HOME/.claude/settings.json и не учитывает CLAUDE_CONFIG_DIR.

5. Предложение для шага 2

moku-rails handoff — чекпойнт и продолжение сессий при смене способа входа. Это не ротация аккаунтов ради лимита.

  • handoff save — пишет ~/.claude/moku/handoff.json: для каждой открытой moku-сессии id, cwd, станцию и открытое изменение, а также сводку незакоммиченного (число файлов, ветку). Без содержимого и без секретов.
  • Переход — только официальными командами: claude auth login --console (API-ключ), Team-аккаунт, /usage-credits или профиль CLAUDE_CONFIG_DIR для рабочего аккаунта. moku только печатает команду, токенов и Keychain не касается.
  • handoff resume — печатает по каждой сессии cd <cwd> && claude --resume <id> (или --desktop), проверяет привязку к рельсам и подсказывает станцию.
  • Попутно: detect-moku-project.sh начнёт учитывать CLAUDE_CONFIG_DIR.
  • Чего не будет: автоматического переключения по сигналу лимита и сценария «второй личный аккаунт».

Решение за пользователем: (а) строить handoff в таком виде; (б) не строить и пользоваться Extra usage или Ultra; (в) уточнить вопрос в поддержке Anthropic, прежде чем что-то делать с двумя личными подписками.
